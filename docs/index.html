The idea

Every coding agent needs an API key. CloseNI doesn't. It opens a real browser, signs into DeepSeek, Qwen or GLM the way you would, and then drives that chat window as if it were an API — sending prompts, reading replies out of the page, parsing them into file changes, applying them, and checking that the result compiles.

What it does

No key required

Playwright drives a real signed-in session. Your provider account is the only credential.

Plans that fit the work

The model decides how many steps a project needs — two for a script, twenty or more for an application.

Parallel steps

Independent steps run at once in separate tabs. Conversations parallelise; file writes never do.

Self-healing

A failed syntax check goes back to the model with the error, and it tries again.

Six languages

Python, JavaScript, Rust, C, C++, Java. A manifest means one project check; no manifest means one per file.

Projects that run themselves

Every build writes a run manifest and scripts, so reopening a project next month still knows the command.

Ask about a failure

The Test chat carries the last command and its output with it. You never paste a traceback.

Nine themes

Including CRT variants and a high-contrast fallback. The swatches above are four of them.

Commands that install system packages, run as root, or pipe a download into an interpreter always ask — whatever the permission setting says. And an environment that cannot build a virtualenv no longer fails code that already compiled.

First launch downloads a browser. CloseNI drives real browsers, so it fetches its own Chromium — about 389MB, once, kept in your user data directory. Bundling it would put half a gigabyte in every release.

How it is built

Two processes with one contract between them. The desktop app never touches a browser; the agent never touches a window. The agent is a command-line program you can run by hand, which is exactly how its end-to-end suite drives it — against a mock chat server, with only the model's answers faked.

  desktop/          Electron — panels, plan review, diffs, settings
    main.js         IPC, git, the GitHub token
    builder.js      the step scheduler
       │  spawn, JSON over stdio

  local-agent/      TypeScript, one process per task
    providers/      send · wait for the reply · read it out of the page
